## ⚡ SEO 頁面速度升級為 Core Web Vitals（2026-06-10 加入）

**動機：** 現有 [seoAnalyzer.js checkPageSpeed()](../src/services/seoAnalyzer.js) 只測 TTFB（拿到第一個 byte 的時間）、不測 Google 真正用來排名的 Core Web Vitals（LCP / CLS / INP / FCP）。客戶看到「SEO 速度 100 分」、其實不代表 Google 認可。

**升級方案：** 接 Google PageSpeed Insights API
- 免費配額 25,000 query/天、完全夠用
- 回傳真實 CrUX（Chrome 用戶實測資料）+ Lighthouse 合成測試
- 輸出完整 Web Vitals 數字 + 評分

**工作量：** 半天
- 後端 `/api/page-speed?url=` proxy 到 PSI API
- 前端 SEOAudit 頁顯示 LCP / CLS / INP 三個主指標
- 更新 score 計算邏輯（綜合 Web Vitals 而非單一 TTFB）

**優先：** 不急、SEO 分數的 leading indicator 本來就不等於業績。等想法 2 媒體提及 MVP 跑完再做。

## 🎯 分數天花板與「Leading vs Lagging」UX 重新框定（2026-06-10 加入）

**動機：** 第一位付費客戶 + yuppy0912 都遇到「某些訊號層做到 100 分了、但 aivis 引用率還是 0、客戶質疑為什麼」。用戶曾考慮把分數降到 95 上限留想像空間、但會有副作用（永遠拿不到滿分的挫敗 / 與市場標準不一致 / 沒解決根問題）。

### 問題的真實本質

**Leading vs Lagging indicator 混淆：**

| 指標類型 | 5 訊號層對應 | 意義 |
|---|---|---|
| **Leading（你做了什麼）** | SEO / AEO / GEO / E-E-A-T audit 分數 | 「具備被 AI 引用的條件」 |
| **Lagging（市場給你什麼）** | aivis 引用率 + 媒體提及 | 「實際被 AI / 市場引用了沒」 |

客戶把「audit 滿分」誤解為「業績滿分」。Audit 100 = 舞臺搭好、不等於觀眾入場。

### 不做的事

- ❌ **不降天花板**（保持 100 滿分）— 降天花板會：
  - 客戶看 95 問「為什麼差 5、要怎麼補」、答案是「沒得補」、更挫敗
  - Yoast / Rank Math 都用 100、特立獨行客戶會質疑
  - 失去用「100」當行銷符號的機會（升級漏斗 85 → 92 → 100 心理推力強）

### 該做的事

1. **UI 文案調整**：100 分後加 **「audit 完美 ≠ 業績滿分」** 的明確說明
2. **滿分達標 next step 卡**：5 訊號層全綠或 overall ≥ 90 時、彈 next step 引導：「下一步是 aivis 引用率追蹤 + 外部訊號（媒體提及）」
3. **儀表板分區重新設計**：把「基礎建設分」（5 訊號層 audit）和「市場結果分」（aivis + 媒體提及）視覺分開、不混在同一張卡

### 優先順序

- **短期（1-2 週）**：UI 文案 + 滿分引導卡（半天工作量）
- **中期**：跟想法 2「媒體提及」合做、形成「外部訊號儀表板」（aivis + 媒體提及並排）

## 📡 媒體提及（Brand Mentions）功能（2026-06-10 加入）

**動機：** AI 是「外部訊號驅動」的、不是「網站內部」驅動的。網站 Schema 再完美、Mobile01 / PTT / 新聞沒人提你、AI 還是不會推薦你。傳統 SEO 工具（Ahrefs / SEMrush）做 backlink 監測、但對 LLMO 角度沒人做。

### 為什麼是必做

1. **直接解決客戶痛點**：「audit 100 但 AI 不提我」的根因之一就是外部訊號不夠
2. **代理商銷售神器**：「你品牌被提到 5 次、競品被提到 80 次、所以 AI 推他不推你」對代理商談客戶極致有力
3. **補完 LLMO 訊號鏈**：從「內部 audit」延伸到「外部市場訊號」

### 技術選型（推薦 Google Custom Search API）

| 路徑 | 可行性 | 成本（Pro 月查 1 次每站） |
|---|---|---|
| **Google Custom Search API** ⭐ | ✅ 可行 | 免費 100 query/天、超過 $5/1000、預估 1000 用戶才會超過免費額度 |
| SerpAPI / DataForSEO | ✅ 可行 | $50-100/月、配額大 |
| 爬蟲自建 index | ❌ 太重 | 不適合 SaaS |
| aivis 同 stack 問 AI | ⚠ 部分 | aivis 已部分做到 |

### 設計方向（不打亂 5 訊號層架構）

**選 B（推薦）：放在 aivis 旁邊、做「外部訊號儀表板」**

- aivis 監測「AI 有沒有提你」
- 媒體提及監測「網路有沒有提你」
- 兩者並列、清楚對比：
  - 健康：「網路提及 50 次 + AI 提及 3 次」
  - 不健康：「網路提及 5 次 + AI 提及 0 次」
- 直接告訴客戶「外部訊號不夠是 AI 不提你的根因」

選 A（放 GEO 下）也可、但會把 GEO 變超複雜、選 B 視覺更清楚。

### MVP 範圍

1. **Pro / Agency 用戶可手動觸發查詢**（首版不自動）
2. **抓品牌名提及次數**（用 Google Custom Search、`"品牌名" -site:你的網域`）
3. **來源網域分類**（新聞 / 部落格 / 論壇 / 社群、按 domain authority 加權）
4. **競品比較**（輸入競品品牌名、並排比較被提及次數）
5. **可操作建議**：提及少時建議「投新聞稿 / 鋪論壇 / 找 KOL / 投產業媒體 / 編 Wikipedia」

### 優先順序

- **MVP**（3-5 天）：基本查詢 + 來源分類 + 顯示
- **進階**（再 2-3 天）：競品比較圖 + 自動週報
- **整合**：跟想法 1 的「外部訊號儀表板」一起做、視覺一致

## 🏗 Agency 方案完整實作（2026-06-09 加入、2026-06-09 拍板）

**動機：** 2026-06-09 正式上線時 Agency 方案還是「籌備中」、用戶決定不等候補名單、直接動工。用戶本身就是代理商（優勢方舟）、他的需求就是 first-hand 資料。

### 4 個設計問題已拍板（2026-06-09）

| 問題 | 拍板答案 |
|---|---|
| **Q1：客戶站怎麼隸屬代理商？** | **B. 代管模式** — 代理商直接擁有客戶站、客戶不需自己帳號。Phase 2 再考慮升 A（viewer 權限） |
| **Q2：白標到什麼程度？** | **Lv 1（PDF 白標、已有）+ 客戶獨立分享連結**。Lv 2 子網域 / Lv 3 完全白標等真實 Agency 用戶反饋再做 |
| **Q3：定價結構？** | **2 階梯**（細節下方） |
| **Q4：計費方式？** | **年月雙軌**（同 Pro 邏輯、年繳 ~17% 折扣） |

### 💡 關鍵 insight：代理商願付客戶是漏斗、不是 1:1

**用戶觀察：** 代理商管 100 個客戶、但能說服去買 LLMO 的客戶通常只有 10-30%。意思是「Agency 100 站」涵蓋到的代理商遠比想像大。

| 代理商規模 | 總客戶數 | LLMO 願付客戶 (10-30%) | 對應方案 |
|---|---|---|---|
| 小工作室 | 5-15 | 1-5 | **Pro 還夠用**（15 站）|
| 小型代理商 | 16-50 | 5-15 | **Agency Starter（30 站）** |
| 中型代理商 | 50-150 | 15-50 | **Agency Plus（100 站）** |
| 大型代理商 | 200+ | 50-100 | Plus 也夠用、超過再 case-by-case |

**結論：Phase 1 兩階梯就涵蓋到 99% 代理商客群、不需要做「不限站」的 Agency Pro**。

### 拍板定價

| 方案 | 月費 | 年費（省 17%） | 站數 | 重點 |
|---|---|---|---|---|
| **Agency Starter** | NT$4,990 | NT$49,900（月攤 4,158） | **30 站** | 多客戶工作區 + PDF 白標 + 優先客服 |
| **Agency Plus** | NT$9,900 | NT$99,000（月攤 8,250） | **100 站** | 全部 Starter 功能 + 客戶獨立分享連結 + 客戶帳號邀請 |
| Agency Pro（未來） | TBD | — | 不限 | 子網域白標、API、SLA — 等需求出現再做 |

**為什麼這樣設：**
- Starter 30 站（非 50）— 把「真正小代理商」框出來、避免中型代理商付 4,990 就夠用
- Plus 100 站 = 3.3 倍站數但只 ~2 倍價、給中型代理商「升級有甜頭」
- 兩階梯之間有功能差（不只站數差）、升級理由清楚
- 年繳 17% off 同 Pro 邏輯

### 代理商銷售彈藥包（新增、Phase 2）

**動機：** 代理商最大阻力不是「沒監測工具」、是「賣 LLMO 給客戶很難」。Aark 提供「彈藥包」幫代理商說服客戶、是留住 Agency 用戶的最強鉤子。

| 彈藥 | 工作量 | 優先 |

## 💡 WordPress 插件化（2026-06-09 加入）

**來源：** 第一位付費客戶 yuppy0912 反饋「修網站時要在原網站和 Aark 來回切換很煩」、進而建議「能不能做 WordPress 外掛、像 Yoast / Rank Math 那樣裝在 WP 後台、順便做全世界 WP 用戶的生意」。

### 戰略價值（為何值得認真想）

| 槓桿 | 對 Aark 的具體效益 |
|---|---|
| 70M WP 站的分發通路 | wordpress.org 是世界最大免費獲客來源、抓 0.01% = 7,000 站 |
| 零摩擦入門 | 30 秒裝完、不用註冊網站、Free 版直接體驗 → Pro 漏斗自然 |
| 黏著度暴增 | 插件活在每天的 WP 後台、留存遠勝獨立 web tool |
| 修復一鍵化 | 從「告訴你紅燈」升級為「一鍵自動套 Schema / llms.txt」、徹底解客戶切換痛點 |
| 戰略卡位 | Yoast / Rank Math 還沒做 LLMO、拿下「LLMO 之於 WP」這個 niche、後續難被超車 |
| 跨平台複製 | 走通後可複製到 Shopify App Store / Wix App Market / Webflow Apps |

### 隱性成本（為何不能輕率上馬）

| 成本項 | 嚴重度 |
|---|---|
| **PHP / WP 技術棧不同** | 現在 React/Vite stack、寫真實 WP 插件要 PHP + Hooks + REST API、不同技能 |
| **WordPress.org 審核** | GPL 開源、安全審核嚴格、首次送審 2-4 週、被退回常見 |
| **付費版要拆兩個插件** | 慣例：免費 + Premium 各一個 plugin、維護複雜度 ×2 |
| **Yoast / Rank Math 共存** | 用戶通常已有 SEO 外掛、要當補位非取代、相容性測試成本 |
| **i18n（國際化）** | 全球發行要多語、現在所有 UI / 文案是中文、要全 extract 成翻譯字串 |
| **兩個產品同步維護** | Web app + WP plugin、功能漸漸分歧、技術債翻倍 |

### 兩條實際路線

**路線 A — 薄殼插件（驗證用、1 個月）**
- iframe / API 嵌 Aark dashboard 進 wp-admin
- 全部分析跑在 Aark 後端
- 加 1 個殺手功能：「一鍵注入 Schema」（PHP 直接寫 head、免裝 WPCode）
- 目的：驗證需求、收 1-2 個月用戶數據

**路線 B — 原生 WP 插件（押大注、3-6 個月）**
- 完整 PHP 重寫 5 訊號層分析、本地跑（更快、無 API 依賴）
- 完整 wp-admin UI / 儀表板 / 修復面板
- 全部 fix 一鍵自動套（Schema / llms.txt / robots.txt / meta）
- API 只留給 aivis 跨 LLM 監測（無法本地做）
- 定位：「Yoast Killer for LLMO」、Pro 訂閱核心鉤子

### 決定前要回答的 3 個問題

1. **P0 是代理商還是 WP 站主？**
   - 代理商不一定能在客戶 WP 裝外掛（需客戶授權）
   - WP 站主才是直接受益者
   - 影響插件設計優先順序
2. **有 PHP / WP 開發者嗎？**
   - 現在 React/Vite stack
   - 要不要外包 / 找新人 / 學新技能、影響估時
3. **準備好做英文版嗎？**
   - 全球發行最大門檻不是技術、是 i18n + 英文 marketing copy + 客服

### 暫定結論（2026-06-09）

**目前不啟動、原因：**
- 上線阻擋未除（公告文案 + 客服通道）、應先把現有產品穩定起來
- 沒有真實使用數據、不知道「跨網站切換」是不是真痛點還是 anecdote
- P0 是代理商、代理商在客戶 WP 裝外掛的場景有限

**何時重新評估：**
- 上線後 1-2 個月、有 20+ 真實付費代理商 / 站主使用
- 看實際反饋裡「我想要 WP 插件」的呼聲有多大
- 同時看 Agency 多客戶工作區的 ROI 是不是更高

**如果決定做、最務實的開始：**
路線 A 薄殼版、聚焦「一鍵注入 Schema」這個殺手功能、1 個月驗證需求、再決定要不要押路線 B。
